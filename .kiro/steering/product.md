# プロダクト概要

「赤煉瓦文化館 〜こっちにおいで〜」は、福岡市赤煉瓦文化館（現エンジニアカフェ）を舞台にした体験型Webホラーゲームです。ハッカソンプロジェクトとして開発され、以下の3つの主要コンポーネントで構成されています：

## アーキテクチャ構成

- **フロントエンド**: Next.js 15.5.2 + React 19.1.0 + TypeScript（App Router使用）
- **バックエンド**: Go 1.25.1 REST APIサーバー（レイヤードアーキテクチャ + DDD）
- **インフラストラクチャ**: AWS ECS Fargate + Terraform（本番環境対応）

## プロダクトコンセプト

### 目的
- 福岡市赤煉瓦文化館の歴史的連続性（1909→資料館→文化館→現在）を「体験」として理解させる
- 恐怖→解放→内省の感情の揺れを使い、プレイヤー自身の「理想」「生きる意義」の記憶を呼び戻す
- 最後に自分のメッセージを刻ませることで、「この建物は受け継がれてきた/自分も受け渡す側になる」という構図を体感させる

### 想定プレイヤー
- エンジニアカフェの来館者
- 赤煉瓦文化館の歴史紹介イベント参加者
- デジタル/ARコンテンツに抵抗のない20〜40代社会人

### プレイ時間・運用
- 所要時間：20〜30分（館内移動込み）
- 1セッション有効時間：開始から60分でサーバ側セッション破棄
- 同時接続：標準10人、最大30人を目標（技術的にはECSで水平スケール）

## 主要機能

### ゲームフロー
1. QRコードから起動（URL固定）
2. カメラ/音声許可 → イヤホン着用案内 → 注意書き（ホラー演出あり）
3. 1942年への時代遡行演出＋担当者との対話（生命保険の診査としての来館）
4. 建物内の5つの「お気に入りの場所」を教えられる（後の探索に必須）
5. 2階の診査室に行くように指示され、途中でホラー演出が入る
6. 診査室での「内省の10問」：子ども時代〜今の願望までを答えさせる
7. 診査完了直後、「死亡届が受理されました。7分以内に担当者の存在証明書と交換してください」と通知（1972年パート）
8. 館内5カ所を7分以内に巡り、各地点で"担当者との記憶のシンクロクイズ"に1回正解してピースを取得（5/5で完成）
9. 2002年パートで担当者のメッセージを受け取り、自分の「人生の最期に達成したいこと」を一字一句で再現
10. 現在（2025年）に戻り、メインホールのどこに自分のメッセージを残すか選んで終了
11. 入力されたメッセージは次のプレイヤーのどこかで匿名的に使われ、歴史を紡ぐ

### 技術的特徴
- **音声の動的生成**：VOICEVOX（青山龍星(しっとり)）をEC2上で動作させ、アプリケーションサーバからHTTPで音声を生成する
- **AR的演出**：カメラ映像にホラー用オーバーレイ（影・虚な人）を重ねる
- **画像認識**：館内5カ所の撮影画像を基準画像と類似度比較して場所到達を判定
- **匿名継承コンセプト**：過去プレイヤーの回答が匿名化されて次のプレイヤーのクイズのダミーになる

### インフラストラクチャ
- **コンピュート**: ECS Fargate クラスター（コンテナ化されたAPIとWebサービス）
- **ロードバランサー**: ALB（パスベースルーティング：`/` → Web、`/api/*` → API）
- **データベース**: RDS MySQL（セッション管理、プレイヤー回答、メッセージ保存）
- **ストレージ**: S3（静的アセット、撮影画像、音声ファイル用）
- **音声生成**: EC2上のVOICEVOXサーバ
- **画像認識**: gRPCマイクロサービス（Python）
- **ネットワーク**: カスタムVPC（パブリック/プライベートサブネット）
- **コンテナレジストリ**: ECR（APIとWebイメージ用）

## 開発段階

現在は本格的なプロダクション対応に移行済み：
- ドメイン駆動設計（DDD）の完全実装
- MySQLデータベース対応（ゲームセッション、プレイヤー回答、メッセージ保存）
- Dockerコンテナ化とCI/CD自動デプロイ
- AWS ECS Fargateでの本番環境運用

**重要**: このプロジェクトはPoC（Proof of Concept）として開発されています。そのため、**いかなる場合もテストコードの作成は不要**です。開発速度とプロトタイピングを優先し、テストコードの実装は求められません。

## コミュニケーションルール

## コード品質ルール

- **コード変更時は必ずlintチェックを実行し、エラーがないことを確認する**
- フロントエンド: `pnpm lint` を実行してESLintエラーがないことを確認
- バックエンド: `make fmt && make lint` を実行してフォーマットとlintエラーがないことを確認
